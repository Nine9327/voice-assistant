# 本地语音助手

按住空格说话，松开后自动识别、思考、开口回答。也可以直接说唤醒词，或者点一下桌面上的形象。
启动后用浏览器打开配置页，可以随时切换每一环用本地还是网络服务。

三种叫醒方式共用同一条链路：

```
按住空格 ─┐
说唤醒词 ─┼→ 录音/取文本 → 识别 → 大模型 → 逐句切分 → 合成 → 扬声器
点桌面形象 ┘
```

中间还有三个岔路口，走的是更快的路：

* **「打开微信」这类本机指令直接执行**，查表就能办的事不去惊动大模型，反应是瞬间的；
* **问「今天天气」「有什么新闻」时先去网上查一段**，把结果塞给模型再开口，省得它拿训练数据里的旧世界一本正经地编；
* **接上 MCP 服务器之后，模型可以自己动手**：读文件、查日历、连数据库都行，它决定调哪个工具、传什么参数。

双击 `start.vbs` 同时拉起助手和桌面形象，全程没有命令行窗口；要停就双击 `stop-all.bat`。

## 链路

```
麦克风 → 识别 → 大模型 → 逐句切分 → 语音合成 → 扬声器
```

每一环都有两套服务可选，在配置页里点一下就能换：

| 环节 | 本地（默认） | 网络 |
|---|---|---|
| 识别 | faster-whisper small，GPU 0.15s | OpenAI 兼容 `/audio/transcriptions` |
| 大模型 | Ollama `qwen2.5:7b` | 任意 OpenAI 兼容接口（DeepSeek、硅基流动、百炼、智谱…） |
| 合成 | Windows SAPI，稳定 54ms | edge-tts，音质接近真人 |

默认组合是「本地识别 + 本地模型 + 在线合成」，只有语音合成需要联网。断网时把合成切成离线引擎即可完全离线运行。

## 环境

| 项目 | 版本 |
|---|---|
| Python | 3.11（conda 环境 `voice-assistant`） |
| GPU | RTX 4060 8GB（7B Q4 + whisper small 可共存） |
| 大模型 | Ollama + `qwen2.5:7b` |
| 识别 | faster-whisper `small`，float16，CUDA |
| 合成 | edge-tts `zh-CN-XiaoxiaoNeural`（需联网） |

## 安装

```bash
conda create -n voice-assistant python=3.11 -y
conda activate voice-assistant
pip install -r requirements.txt
pip install nvidia-cublas-cu12 nvidia-cudnn-cu12   # GPU 识别所需
ollama pull qwen2.5:7b
```

## 使用

### 日常使用（无窗口）

| 双击 | 作用 |
|---|---|
| `start.vbs` | 启动助手 + 桌面形象，**不显示任何命令行窗口**，日志写在 `.runtime/*.log` |
| `stop-all.bat` | 关掉助手、桌面形象和 Ollama，释放全部显存 |

用 `start.vbs` 启动后，配置页不会自动弹出：右键点桌面上的形象 → **打开配置页**。
同一个菜单里还有 **开始说话**、**始终置顶**、**退出程序**。左键点一下形象 = 说一句话，
按住拖动可以换位置（位置会记住）。

### 命令行

```bash
python assistant.py              # 正常语音交互，同时开配置页
python assistant.py --config     # 只开配置页（不占麦克风、不加载模型）
python assistant.py --no-web     # 不启动配置页
python assistant.py --no-wake    # 不监听唤醒词，只留按住空格
python assistant.py --port 9000  # 换端口（默认 8765，占用时自动顺延）
python assistant.py --text "你好" # 跳过录音，测大模型+播报
python assistant.py --text "打开记事本"      # 测本机指令（会真的启动）
python assistant.py --text "今天有什么新闻"   # 测联网搜索
python assistant.py --no-audio   # 只打字不播报
python pet.py                    # 单独起桌面形象（python pet.py --debug 带日志）
python selftest.py               # 端到端自检（合成语音当输入，不需要麦克风）
python voices.py                 # 音色列表 / 试听
python stop.py                   # 一键关闭
```

只想调配置：双击 `config.bat`（或 `python assistant.py --config`）。
想看到控制台输出、排查问题：双击 `run.bat`。

操作：**按住空格**说话，松开即开始回答；回答过程中再按空格可以打断它。`Ctrl+C` 退出。

## 唤醒词与桌面形象

`assets/pet.png` 是抠好透明通道的形象（由 `python pet_asset.py` 从原图生成，边缘做了羽化，
深色壁纸上也不会出现白边）。它跑在**独立进程**里，通过本机 HTTP 和助手通信：

* 界面崩了不影响语音，语音卡住也不影响拖动窗口；
* 配置页端口顺延（8765 被占）时，形象靠 `.runtime/server.json` 找过来；
* 助手没起来时气泡显示「启动中…」，几秒仍连不上才提示「没有连接到助手进程」。

唤醒词默认是「小蓝小蓝」，在配置页「唤醒与形象」里改，**保存即刻生效**（不用重启）：

| 项 | 说明 |
|---|---|
| 常开唤醒 | 关掉后只能按住空格或点形象。开着时每说完一句会转写一次（rtf≈0.05，约占 5% GPU 时间） |
| 唤醒提示词 | 建议 3~6 个字；叠词（小蓝小蓝）比单词更不易被日常聊天误触发 |
| 灵敏度 | 越大越容易判定为说话。嘈杂环境调低，小声说话调高 |
| 断句静音 | 说完后停顿多久算一句结束 |
| 连续对话 | 唤醒后多久之内可以直接接着说，0 = 每句都要喊提示词 |

提示词后面的内容会被当成这一次的指令：「小蓝小蓝，今天天气怎么样」一句话说完即可，
不用先唤醒再重复一遍。

**判定按「同音」而不是「同字」**：先把每个字转成不带声调的拼音，再滑动窗口对齐，
所以 whisper 听成「小兰小兰」「小男小男」「晓岚晓岚」「小懒小懒」都能命中。
还把易混的声母韵母归一了（`zh/z`、`ch/c`、`sh/s`、`n/l`、`ang/an`、`eng/en`、`ing/in`），
因为中文语音里这些本来就分不清——实测最常见的是把「小蓝」听成「小男」，不归一就永远唤不醒。
两个字的提示词要求读音全对，否则「小红」也会唤醒「小蓝」。

## 连续对话与休眠

一次唤醒之后默认有 **20 秒**的「会话期」（配置页「连续对话」可调，0 表示关掉）：

```
休眠 ──说提示词──▶ 会话中：开口就说，说完它接着说下一句
  ▲                                │
  └──────── 20 秒没人说话 ──────────┘
```

也就是说唤醒一次可以连着问好几句，不用每句都喊提示词；一直没人说话就自动转回休眠，
再喊一次提示词才重新激活。桌面上形象的状态点会变暗（休眠）/ 变红（在听）/ 变绿（在说），
配置页那行状态会显示「等提示词激活」或「会话保持 剩余 Ns」。

会话期里的话筒是常开的，所以加了两道防自激的锁：播报真的放完才开麦（`Speaker.wait_done`
从「取到任务」就开始计时，而不是等真正出声），以及听到的内容和刚播报的高度重合时直接丢掉。

配置页里有个**验证提示词**的输入框：随便输一句话，直接看它认不认，不用反复对着麦克风试。
它上面那行「监听状态」会实时显示匹配方式（同音/逐字）、最近听到的内容、峰值电平和当前阈值，
调参时看这里最直观。

唤醒判定前有一道**能量门槛**：95 分位数幅度低于门槛的片段直接丢掉。因为 whisper 在近乎
静音的片段上会凭空编出整句话，既白烧显卡，又污染状态显示。门槛跟着灵敏度反向走，
灵敏度拉满时最宽松。

识别端还有第二道防线：`vad_filter=True`（faster-whisper 内置的 silero VAD）会先把非语音段
切掉再解码。不开这一项时，环境噪声会被 whisper 转成它训练集里的字幕套话——实测反复冒出
「请不吝点赞 订阅 转发 打赏」——连续对话模式下就变成对着空气自说自话。

## 联网搜索

问「今天天气怎么样」「最近有什么新闻」「英伟达现在股价多少」，本地 7B 模型的训练数据早过期了，
它会一本正经地编。开启联网后，这类问题先去网上捞一段资料，再让模型**照着资料**说。

**什么时候查**（默认「按问题判断」，纯本地规则，零延迟）：

| 说法 | 判定 |
|---|---|
| 今天天气怎么样 / 最近有什么新闻 | 查（时效词 + 事实词） |
| 帮我查一下明天北京的天气 | 查（明确要求） |
| 英伟达现在股价多少 / 汇率是多少 | 查 |
| 现在几点 / 今天周几 / 今天几号 | 不查 —— 本地注入真实时间，直接答 |
| 你好 / 讲个笑话 / 开个玩笑 / 今天有点累 | 不查 |

比的是打分不是「命中任一关键词」：「今天」单独出现只值 3 分，够不到阈值 4，所以
「今天有点累」不会白跑一趟搜索。

**搜索服务**：默认必应，走 `cn.bing.com/search?format=rss` 的 RSS 输出 —— 免 Key、国内能直连、
结构稳定（不用解析网页 HTML，也不怕反爬改版），实测 300~400ms 返回。另外三种需要自己准备：

| 服务 | 需要 | 说明 |
|---|---|---|
| 必应 | 无 | 默认，够用就别换 |
| Tavily | API Key | 为喂大模型设计的摘要，质量最好 |
| 博查 | API Key | 国内服务，中文结果好 |
| SearXNG | 实例地址 | 自建才稳，公共实例大多连不上 |

资料是**临时插进这一轮**的，不写进对话历史：否则下一轮它还会引用上个问题的旧网页。
搜索失败（超时、没 Key、网络不通）就当没查到，照常回答，不会卡住整轮对话。

## 语音打开应用

说「打开微信」「启动计算器」「把画图打开」，直接执行，不经过大模型 —— 所以是**瞬间**的，
而且不消耗显卡。

应用名按**同音**匹配：「威信」「维信」「记是本」「计祘器」都认得。名字从三个地方来：

1. **内置表**：记事本、计算器、画图、任务管理器、设置、截图工具等 Windows 自带的，不依赖安装位置；
2. **开始菜单**：扫 `.lnk`，一百多个文件只要 20 毫秒，覆盖微信、QQ、Chrome 这类桌面程序；
3. **商店应用**：前两级都找不到时才去拉一次 `Get-StartApps`（结果缓存一周），
   所以「打开照片」这种 UWP 应用也能开。

**安全边界**：只在索引里查，查到才启动，查不到就当成普通聊天交回大模型。所以：

* 不会执行任意命令，也不会打开索引之外的路径；
* 「开个玩笑」不会被当成启动指令（单个「开」字属于弱意图，必须真查到应用才接管）；
* 「打开微信然后给张三发消息」这种复合指令不接，交回大模型 —— 否则会变成「只说了一半就动手」。

## MCP 工具

说「看看我项目的 README 写了什么」「今天日历上还有什么会」，这类事本机模型做不了 ——
它需要**真的去读文件、真的去查日历**。MCP（Model Context Protocol）就是给模型装手的协议：
每个服务器对外暴露一组函数，模型自己决定什么时候调用、传什么参数。

配置页左侧「MCP 工具」里维护服务器清单，也可以直接改 `mcp.json`（格式和 Claude Desktop、
Cursor 那些客户端一致，别人的配置可以整段抄过来）：

```json
{
  "mcpServers": {
    "filesystem": {
      "type": "stdio",
      "enabled": true,
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "D:\\workspace"]
    },
    "remote": {
      "type": "http",
      "enabled": false,
      "url": "http://127.0.0.1:8000/mcp",
      "headers": {"Authorization": "Bearer 在这里放 token"}
    }
  }
}
```

两种传输都支持：

| `type` | 说明 | 典型写法 |
|---|---|---|
| `stdio` | 本地子进程，走 stdin/stdout 收发 JSON-RPC | `npx`、`uvx`、`python xxx.py` |
| `http` | 远程流式 HTTP（旧的 `sse` 已并入这一种） | `url` + 可选 `headers` |

一轮对话里发生什么：

```
你说话 → 模型看工具清单 → 决定调 filesystem__read_file
       → 本地执行 → 结果回填 → 模型组织成口语 → 播报
```

工具结果是**临时**塞进这一轮的消息里的，不写进对话历史 —— 否则上一轮的整篇网页会一直占着
4K 上下文，下一句闲聊都会被它带偏。结果超过 1600 字会截断。

几条刻意的限制：

* **工具名带服务器前缀**：`filesystem__read_file`，避免两个服务器都有 `search` 时互相盖掉；
  中文服务器名会被洗成下划线，因为模型只接受 `[A-Za-z0-9_-]`；
* **最多 `MCP_MAX_TOOLS` 个工具进提示词**：7B 模型工具一多就挑不准，宁可只留常用的几个；
* **最多 `MCP_MAX_ROUNDS` 轮**：防止「调工具→再想→再调」死循环；
* **模型不支持工具调用会自动退回**：报错信息里带 tool/function 就当作不支持，这一轮按普通对话回答，
  不会因为一个可选能力把整个助手搞挂；
* **只执行配置里写死的命令**，语音指令永远只影响「调哪个工具、传什么参数」，不能改命令本身。

配置页里每个服务器都有「测试」按钮：真的把进程拉起来、握手、列工具，然后立刻关掉，
所以能在保存之前就确认命令写没写对。保存后是后台重连的，不用等。

>`mcp.json` 里可能有 token，已加进 `.gitignore` 和提交前的敏感信息扫描；仓库里只留 `mcp.example.json`。

## 配置页

启动后浏览器会自动打开 `http://127.0.0.1:8765`（用 `start.vbs` 启动时不自动开，走形象的右键菜单），
控制台也会打印地址。页面按功能分成九个模块，左侧导航切换，右下角统一保存：

| 模块 | 能改什么 |
|---|---|
| 总览 | 八张状态卡片，点一下就进对应模块；带橙点的模块表示有改动还没保存 |
| 大模型服务 | 本地 Ollama ↔ 网络接口（含 DeepSeek、硅基流动、百炼、智谱、Moonshot 预设）；模型、温度、上下文、记忆轮数 |
| MCP 工具 | 总开关、调用轮数、单次超时、工具上限；服务器清单增删改、逐个测试、全部重连 |
| 语音识别 | 本地模型 ↔ 网络接口；GPU/CPU、模型大小、解码宽度 |
| 语音合成 | 在线 edge-tts ↔ 离线系统语音；音色、语速、音调，可当场试听 |
| 唤醒与形象 | 唤醒开关、提示词、灵敏度、断句静音、连续对话时长；提示词匹配自测、实时监听状态 |
| 联网搜索 | 关闭 / 按问题判断 / 每次都查；搜索服务（必应免 Key、Tavily、博查、SearXNG）、Key、结果条数、超时；试搜一句 |
| 语音打开应用 | 开关；试打开一个应用；显示本机一共认出多少个可打开的程序 |
| 交互与页面 | 最短/最长录音时长、配置页端口 |

切模块不会丢改动（表单一直在 DOM 里，只是隐藏），地址栏带 `#模块名`，刷新或直接访问
`#mcp` 都能停留在同一页；`Alt+1` ~ `Alt+9` 是快捷键。

「保存并应用」之后：

* 大模型、语音合成、唤醒开关的改动**立即生效**，因为这几个模块都重新读配置；
* 识别相关的改动会**自动重建识别模型**，页面会回显切换后的设备（如 `cuda / float16`）；
* 改动同时写入 `settings.json`，下次启动自动沿用；
* MCP 的开关与数值走这次保存；服务器清单改动会顺带写进 `mcp.json`（那一页也有独立的保存按钮）；
* 只有端口这类需要重新监听的项会提示「需重启」。

识别服务重建失败时（比如选了网络识别但没填 Key），**配置会自动回退**，内存和 `settings.json` 一起还原，不会留下一个下次启动必然报错的状态。

页面只监听 `127.0.0.1`，写操作还要求一个自定义请求头，防止别的网页跨站改你的配置。API Key 保存后只显示末四位。

## 关闭

双击 `stop-all.bat`（全关），或：

```bash
python stop.py            # 只关助手和形象，Ollama 会问你要不要一起关
python stop.py --all      # 助手 + 形象 + Ollama 全关，立刻释放约 5G 显存
python stop.py --keep-ollama  # 只关助手，不动 Ollama，不弹询问
python stop.py --dry      # 只列出会被关掉的进程，不动手
```

它会结束命令行里带本项目特征的 Python 进程（`voice-assistant` 路径、`assistant.py`、
`pet.py`），**不会误伤你别的 Python 程序**。进程定位优先读 `.runtime/*.pid`，
pid 文件失效时再扫命令行兜底；关完顺手清掉残留的 pid 和端口记录，下次启动不会被旧状态绊住。

Ollama 被 `--all` 关掉后，下次启动助手会自动把它拉起来，不用手动开。

## 实测性能（RTX 4060 8G）

| 环节 | 实时率 / 耗时 |
|---|---|
| 语音识别（3.1s 音频） | **161ms**，rtf 0.05 |
| 大模型首字 | **0.07 ~ 0.19s**（热态） |
| 大模型整段生成 | 0.39s（约 20 字回答） |
| **松手到开口** | **约 0.6 秒** |
| 语音合成 · 在线 edge-tts | 约 1.9s / 句（网络往返为主） |
| 语音合成 · 离线 SAPI | **54ms / 句**（首次含 COM 初始化 240ms） |
| 联网搜索（必应 RSS） | **300 ~ 410ms**，命中缓存则 0ms |
| 打开本机应用 | 查到就启动，**不经过模型**，耗时在 ShellExecute 本身（如「现在是几点」141ms） |
| 首次冷启动 | 约 30s（4.7G 模型载入显存，之后常驻） |

对照：whisper 如果跑 CPU，同段音频要 1.5s，整体延迟翻三倍——所以值得让它挤进 GPU。

## 配置

优先级：`settings.json`（配置页保存的） > `config.py`（默认值）。
`config.py` 里写的是出厂默认，适合设定长期基线；日常调整直接走配置页。
想恢复默认，删掉 `settings.json` 再重启即可。

| 项 | 说明 |
|---|---|
| `LLM_MODEL` | 换模型，如 `qwen2.5:3b`（更快）/ `qwen2.5:14b`（8G 显存跑不动） |
| `WHISPER_MODEL` | `small` 平衡最好；`medium` 更准但 CPU 慢一倍 |
| `TTS_VOICE` | 音色，内置 14 个中文音色，用 `python voices.py` 试听 |
| `TTS_RATE` | 语速，`+12%` 比默认更像真人对话 |
| `TTS_PITCH` | 音调，负值更低沉（`-20Hz`），正值更清亮 |
| `MAX_HISTORY_TURNS` | 记住几轮对话 |
| `WAKE_PHRASE` | 唤醒提示词，建议 3~6 个字、叠词 |
| `WAKE_SENSITIVITY` | 0~1，越大越容易判定为说话；环境嘈杂时调低 |
| `WAKE_SESSION_SECONDS` | 唤醒后保持对话的秒数，0 = 每句都要喊提示词 |
| `SEARCH_MODE` | `off` / `auto` / `always`，控制什么时候联网 |
| `SEARCH_BACKEND` | `bing` / `tavily` / `bocha` / `searx` |
| `SEARCH_KEY` | Tavily、博查的 Key；用必应时留空 |
| `SEARCH_RESULTS` | 取几条网页摘要喂给模型，多了反而跑题 |
| `APPS_ENABLED` | 允许说「打开某某」直接启动应用 |
| `MCP_ENABLED` | MCP 工具总开关；关掉后不启动任何服务器进程 |
| `MCP_CONFIG_FILE` | 服务器清单路径，默认 `mcp.json` |
| `MCP_MAX_ROUNDS` | 一轮对话里最多「调工具→再想」几轮，0 = 只判定不执行 |
| `MCP_TIMEOUT` | 单次工具调用超时（秒） |
| `MCP_MAX_TOOLS` | 最多几个工具进提示词；7B 模型别给太多 |
| `SYSTEM_PROMPT` | 人设与说话风格，直接影响朗读效果 |

## 设计上的几个关键点

1. **显存预算算清楚**：7B Q4 占 4.7G，whisper small float16 只需约 500MB，两者能共存。加载失败会自动回退 CPU，不会卡死。
2. **逐句播报**：大模型流式输出，遇到句末标点就切一句送去合成，播放线程串行消费，所以「边说边想」，不等全文生成完。
3. **打断即闭麦**：按空格立刻停播并清空待播队列，避免麦克风把扬声器的声音录进去造成自问自答。唤醒监听同理——播报期间关掉，一轮对话结束再打开。连续对话模式下更严格：`wait_done()` 从「取到合成任务」就开始算忙，而不是等音频真正开始播，否则中间那几百毫秒的合成窗口足够让话筒把自己的上一句录回来。
4. **形象独立成进程**：Qt 事件循环和语音主循环互不干扰，两者只用本机 HTTP 说话。界面卡住不会拖慢识别，语音卡住也能照常拖动窗口。
5. **配置是活对象**：`config` 模块就是唯一真相，业务模块每次调用都重新读它，所以网页改完即刻生效；`settings_store` 只负责校验和落盘。
6. **能查表就别问模型**：「打开微信」是查表题，交给大模型既慢又危险。只有真的需要组织语言时才调模型，中间还会先判断要不要联网。
7. **时间戳放消息末尾**：真实日期必须告诉模型，否则它拿训练数据里的日期回答「今天几号」。但这条不能塞在第一条 system 里 —— Ollama 按前缀复用 KV cache，每轮都变的前缀等于每轮都让缓存失效，首字延迟会从 0.1 秒涨到 0.5 秒以上。

## 常见问题

**双击 `run.bat` 报「'1' 不是内部或外部命令」「'dp0"' 不是内部或外部命令」**
批处理文件被存成了 LF 换行（或含非 ASCII 字符）。cmd.exe 只认 CRLF，换行不对会把多行命令拼成一团，`%~dp0` 被切碎成 `dp0"`、`if errorlevel 1` 被切出一个孤立的 `1`。
修复：`python tools/normalize_eol.py`（会把 `.bat` / `.vbs` 统一成 CRLF + 纯 ASCII，其余文本转 LF）。`.gitattributes` 已强制 `*.bat` 使用 CRLF。

**首次运行卡在「加载识别模型」**
要从 hf-mirror.com 下约 500MB，走代理可能失败。代码已默认设置 `HF_ENDPOINT=https://hf-mirror.com` 和 `HF_HUB_DISABLE_XET=1`；若仍失败，可手动把模型放到 `models/faster-whisper-small/`。

**启动时提示「GPU 不可用，回退 CPU」**
说明 CUDA 运行库没找到。`pip install nvidia-cublas-cu12 nvidia-cudnn-cu12` 后重启即可。回退后功能完整，只是识别从 0.15s 变成 1.5s。

**按空格没反应**
pynput 监听的是全局键盘。若以管理员权限运行了别的窗口，需以管理员身份运行本程序。

**说了唤醒词没反应**
先在配置页「验证提示词」里输入「小蓝小蓝，现在几点了」点比对：认得出就是识别没问题，
问题在麦克风侧的判定。看下面那行「监听状态」：如果峰值一直低于门槛，说明声音太轻，
把**灵敏度**拉高（门槛会跟着降低）；如果压根没有峰值跳动，就是没听到声音，检查麦克风。
另外回答播报期间唤醒是关掉的（防自激），等它说完再说。

**配置页「最近听到」是一堆莫名其妙的话**
whisper 在近乎静音的音频上会凭空编句子（典型是「请不吝点赞 订阅 转发 打赏」这种字幕套话）。
代码有能量门槛 + silero VAD 两道过滤挡掉大部分，环境噪声特别大时仍可能漏过。
这不影响正确性（编出来的话不会命中提示词），只是白烧一点显卡。把灵敏度调低可以进一步减少。

**它对着空气一直自问自答**
连续对话模式下出现过这个问题，现在有三道锁：播报真的放完才开麦、听到的内容和刚播报的高度重合
就丢掉、识别端 VAD 过滤。如果还复现，先看是不是外接音箱离麦克风太近——把「连续对话」调到 0
（等于每句都要喊提示词）能立刻止损。

**问「今天天气」没联网，还是乱编**
去配置页「联网搜索」点「搜一下」：状态行会同时告诉你两件事——后端通不通，以及这句话在
自动模式下判不判要搜（附打分理由）。如果判断为「不查」，说明这句话没凑够分；
嫌它太保守就把「什么时候查」改成「每次都查」。如果后端报错，多半是网络达不到必应
（换 Tavily/博查）或者 Key 没填。

**说「打开某某」没反应，它却开始聊天**
这说明应用名没匹配上，代码有意选择「找不到就不接管」，免得瞎开东西。去配置页
「语音打开应用」里输入同样的名字点「打开」，命中就会直接启动并回显匹配到的是哪个程序；
没命中就换个更接近开始菜单里显示的名字。应用清单是启动时扫的，刚装了新软件就重启一下助手。

**桌面形象不出现**
看 `.runtime/pet.log`。常见原因是缺 PySide6（`pip install PySide6`）或缺 `assets/pet.png`
（跑一次 `python pet_asset.py`）。形象显示「没有连接到助手进程」说明助手还没起好或已经退出——
它只轮询本机 HTTP，不依赖助手是否先启动。

**双击 `start.vbs` 没动静**
它启动的就是 `pythonw.exe assistant.py --no-browser` 加 `pythonw.exe pet.py`。
没有反应时先在命令行跑 `python assistant.py --no-browser` 看报错——pythonw 不显示控制台，
所以真出了问题得靠这条命令或者 `.runtime/assistant.log` 看。

**回答读出来很生硬 / 带符号**
调 `SYSTEM_PROMPT` 更严厉地禁止 Markdown；`tts.sanitize()` 也会兜底清理。

**想完全离线**
配置页把「语音合成服务」切到**离线系统语音**即可，识别本就在本地、大模型就在 Ollama，切完断网也能用。代价是声音偏机械，但实测单句合成只要 54ms，比在线快得多。

**配置页打不开 / 打开是空白**
先看控制台有没有打印 `配置页 http://127.0.0.1:xxxx`。端口被占用时会自动顺延到下一个，以打印的地址为准。若端口全被占，会提示启动失败，但语音功能不受影响。

**改了配置没反应**
大模型和合成是即时生效；识别会重建模型，页面底部会显示切换结果。若提示「需重启」，说明改的是端口这类监听参数。想让改动彻底生效，重启一次最稳。

**Git Bash / 终端里连不上 127.0.0.1:11434，但 Ollama 明明开着**
`HTTP_PROXY` 没配 `NO_PROXY`，本地请求被送去代理了。代码已对 `127.0.0.1` 自动绕开代理，命令行里手动调接口时记得用 `curl --noproxy '*'`。

**Ollama 起来了但一个模型都没有**
说明它读的是默认目录 `~/.ollama/models`。桌面版如果配置过模型目录（本机是 `D:\AI\ollamamodels`），必须启动 `ollama app.exe` 而不是 `ollama serve`。程序已按这个顺序处理。
